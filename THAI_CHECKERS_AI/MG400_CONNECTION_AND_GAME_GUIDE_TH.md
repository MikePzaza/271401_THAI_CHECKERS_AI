# วิธีเชื่อม MG400 และดูว่าเกมเริ่มจริงหรือยัง — รุ่นแก้ไข

> รุ่นนี้เป็นโปรแกรมควบคุมหุ่นยนต์จริง ไม่ใช่การจำลองเกม/การจำลองหุ่นยนต์ การตรวจ TCP เป็นเพียงการสื่อสาร ไม่ใช่การรับรองความปลอดภัย

## 1. เริ่มต้นบน Windows / VS Code

1. แตก ZIP แล้วเปิดโฟลเดอร์ `THAI_CHECKERS_6x6_DASHBOARD_V6` ใน VS Code
2. เปิด Terminal แล้วรัน `py -3 -m pip install -r requirements.txt`
3. เปิดโปรแกรมด้วย `py -3 main.py` หรือดับเบิลคลิก `RUN_WINDOWS.bat`
4. เลือกระดับความยาก หน้าหลักจะแสดงผล **MG400** พร้อมปุ่ม `ตรวจการเชื่อมต่อ MG400 (ไม่สั่งเคลื่อน)`
5. เมื่อหน้าต่างเล่นเปิดขึ้น ให้ดูป้าย **สถานะเกม**: `ยังไม่เริ่มเกมจริง — ดูภาพเท่านั้น` หรือ `เกมเริ่มแล้ว HH:MM:SS`

## 2. ตั้งค่า IP (ไม่แตะโค้ดเดิมของ MG400)

- ต่อพีซีและ MG400 เข้ากับเครือข่ายเดียวกัน (ใช้สาย Ethernet ตามคู่มืออุปกรณ์)
- ค่าของโปรเจกต์เดิมคือ **192.168.1.6** (มักใช้กับ LAN1); หากใช้ LAN2 เครื่องอาจเป็น **192.168.2.6** ให้ตรวจ IP จริงที่เครื่อง
- กด `ตั้งค่ากล้อง / MG400` → กรอก `IP MG400` → `บันทึก IP / ตรวจ`
- หรือเปิดไฟล์ `robot_connection.json` แล้วแก้ `"ip"` เป็น IP ของเครื่องจริง
- **สำคัญ:** IP นี้ใช้ทั้งตรวจสถานะและเชื่อมต่อเพื่อสั่งงาน **ตอนผ่านการอนุมัติจริงแล้ว** ไม่ต้องแก้ไฟล์ `mg400_visionV4.py`

ทดสอบ Windows PowerShell ได้ด้วย:

```powershell
ping 192.168.1.6
Test-NetConnection 192.168.1.6 -Port 29999
Test-NetConnection 192.168.1.6 -Port 30003
```

หรือดับเบิลคลิก `CHECK_MG400_WINDOWS.bat` เพื่อดูผลการตรวจ MG400 โดยไม่เปิดหน้าจอเกม

## 3. ระบบแปลผลสถานะอย่างไร

| ข้อความที่เห็น | ความหมาย |
|---|---|
| `พอร์ต 29999 ไม่ตอบ` | ยังไม่มีการตอบรับที่ dashboard; ตรวจ IP, สาย, การตั้งเครือข่าย, เปิดเครื่อง, ไฟร์วอลล์ |
| `พอร์ต 30003 ไม่ตอบ` | Dashboard ตอบแล้ว แต่ยังติดต่อพอร์ตสำหรับส่งคำสั่งเคลื่อนที่ไม่ได้ |
| `ติดต่อได้ / 4` | MG400 ตอบรับ TCP แต่ยังไม่ได้ Enable |
| `ติดต่อได้ / 5` | MG400 ตอบรับ TCP และรายงาน Enabled/Idle (ยัง **ไม่** แปลว่าพื้นที่ปลอดภัยพร้อม) |
| `ติดต่อได้ / 9` | MG400 รายงาน Alarm — ห้ามใช้การเริ่มเกมเพื่อเคลียร์ Alarm |
| `ยังไม่เริ่มเกมจริง — ดูภาพเท่านั้น` | เปิด GUI ได้ แต่ **PhysicalMatch ยังไม่เริ่ม** และไม่ส่งคำสั่ง MG400 |
| `เกมเริ่มแล้ว HH:MM:SS` | ระบบยืนยันหมากเริ่มต้นผ่านกล้อง แล้วเข้าสู่เกมจริงแล้ว |
| `MG400 กำลังเคลื่อนที่` | ระบบกำลังส่งคำสั่งจริง — ห้ามเข้าพื้นที่ทำงาน |
| `ตรวจสอบผลการเดินของ AI จากกล้อง` | ส่งคำสั่งหุ่นจบ แต่ **ยังไม่บันทึกตาเดิน** จนกล้องยืนยัน |

โปรแกรมตรวจสถานะโดยส่ง **RobotMode()** บน TCP 29999 และทดสอบเปิดพอร์ต 30003 แล้วปิดซ็อกเก็ตตรวจทันที โดยจะตรวจซ้ำเป็นระยะเมื่อหุ่นยนต์ไม่ได้กำลังทำงาน: **ไม่ Enable, ไม่สั่งเคลื่อน และไม่สั่ง DO/pump** การควบคุมจริงยังใช้ชุด MG400 เดิมเมื่อถึงตา AI ที่ผ่านเงื่อนไขครบเท่านั้น

## 4. ทำไมต่อ TCP ได้แล้ว แต่ยังไม่เริ่มเกม

แม้ `board.npz` จะอยู่ใน ZIP แล้ว แต่ยังต้องสอบเทียบกระดานและตรวจความถูกต้องกับกระดานของคุณจริง รวมถึงตรวจว่ากล้องเห็นหมากสีดำ 6 ตัว สีส้ม 6 ตัว ณ ตำแหน่งเริ่มต้น

**ค่าปัจจุบันใน `live_safety_config.json` ยังเป็น `false` หลายรายการ** โปรแกรมจึงล็อกการเริ่มเกมจริงไว้ตามเจตนาของระบบความปลอดภัย ห้ามแก้ทั้งหมดเป็น `true` เพื่อทดลอง โปรแกรมต้องได้รับการตรวจอนุมัติจากผู้รับผิดชอบเครื่องหลังทดสอบจริงอย่างน้อย:

- ฮาร์ดแวร์ E-stop และระบบกั้นเขต/ป้องกันคนเข้าเขตทำงานจริง
- เซนเซอร์สุญญากาศและค่า DI ทำงานตามที่ตั้งไว้
- ความถูกต้องของ `board.npz`, ระดับ Z, ตำแหน่งหลบ, ระยะหัวดูดและเส้นทางการเคลื่อนทุกจุด
- พิกัดถาดหมากที่ถูกกิน (หากจะเล่นตากิน), ระบบจัดการฮอส (ปัจจุบันยังล็อกอยู่)

เมื่อผู้รับผิดชอบอนุมัติและบันทึกเงื่อนไขจริงตามการทดสอบแล้ว กด `ตรวจ MG400` แล้ว `ตรวจความพร้อม / เริ่มเกมจริง` ในหน้าดูภาพได้ โดยไม่ต้องปิดโปรแกรม

## 5. กรณีการเริ่มเกมสำเร็จ

1. โปรแกรมตรวจกล้องและเงื่อนไขเริ่มต้นได้ครบ
2. แสดงหน้าต่างสุ่มผู้เริ่มก่อน
3. ป้ายเขียว **เกมเริ่มแล้ว HH:MM:SS** ปรากฏ
4. ถ้าคนเริ่ม เดินหมากดำจริงและรอให้กล้องอ่านได้อย่างนิ่ง ถ้า AI เริ่ม จะคำนวณตาและขอการยืนยัน **ก่อนหุ่นยนต์เคลื่อนจริง**
5. หากหน้าจอขึ้น **ยังไม่เริ่มเกมจริง** หมายถึงเปิดหน้าเกมแล้วแต่ยังไม่ได้เริ่มจริง ไม่ควรนับว่าเกมเริ่ม
